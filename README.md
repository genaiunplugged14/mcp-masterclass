# MCP Masterclass

Code and checkpoints for the **MCP Masterclass**, a free video course in 4 modules and 30 lessons
on the Model Context Protocol. You build one server, called Scribe, end to end on the MCP Python
SDK v2: it starts by reading a draft out of Google Drive, learns to edit the real document, gets a
guard and a memory, and ends up deployed off your laptop where other people can install it. The
whole course runs on the free Claude Desktop plan.

Course hub: [genaiunplugged.com/courses/mcp](https://www.genaiunplugged.com/courses/mcp/)

## Checkpoints

Each module has a checkpoint holding the files you need at the start of it, so a bad afternoon in
the previous module never ends the course. The folders under [`checkpoints/`](checkpoints) are the
same files as the zips on the course site, and [`checkpoints/README.md`](checkpoints/README.md)
says what each one holds and which result line to expect from its checks. Grab the checkpoint at
the start of the module, not after something breaks.

## Getting started

You need:

- Python 3.10 or newer
- [`uv`](https://docs.astral.sh/uv/), or plain `pip` inside a virtual environment
- [Claude Desktop](https://claude.ai/download). A free account is enough.
- A Google service account key, `key.json`, which lesson 4 walks you through. It is a password, so
  it is never in this repo and never will be.

Every `requirements.txt` pins the SDK to a range:

```
mcp[cli]>=2.1,<3
```

A lower bound alone is not a pin. The first version of this course said `mcp>=1.0.0`, which later
resolved to version 2 and broke every sample it shipped with.

```bash
git clone https://github.com/genaiunplugged14/mcp-masterclass.git
cd mcp-masterclass/checkpoints/module-1

uv venv && source .venv/bin/activate     # or: python3 -m venv .venv && source .venv/bin/activate
uv pip install -r requirements.txt       # or: pip install -r requirements.txt

python3 verify_drive_access.py key.json
```

You want to see `RESULT: read yes. change yes. create no.` at the bottom. If a read fails you
almost certainly missed the sharing step in lesson 4: sharing the Drive folder with the service
account's email is what grants access, and roles set in the Cloud console do not.

Each checkpoint carries a `verify_claude_config.py` that checks whether Claude Desktop actually
started the servers you configured, and a `claude_desktop_config.json` with `/FULL/PATH/TO/scribe`
as a placeholder. Every path in it must be absolute, and Claude Desktop has to be fully quit and
reopened after you edit it. That is the single most common reason a server does not appear.
